ConnectSphere v1.0

Community-first social networking built on Angular 21 and Spring Boot microservices.

ConnectSphere is a production-style social media platform for identity, posting, comments, reactions, stories, follows, notifications, search, payment-backed verification, and admin moderation. This page mirrors the presentation style of the reference document while using the actual structure and runtime details discovered in the ConnectSphere codebase.

Angular 21 + SSR Spring Boot 3.4.x API Gateway + Eureka MySQL + Kafka JWT + Google OAuth2 11 backend runtime pieces

1Project Synopsis

ConnectSphere delivers a modern social platform experience with a microservice backend and a route-driven Angular frontend. Users can register or sign in with Google, create public or restricted posts, reply in threaded discussions, react to content, publish expiring stories, follow other users, receive in-app notifications, search users and hashtags, and manage profile settings. Administrative users get moderation, verification, user governance, and system-level monitoring capabilities.

Application Type
Distributed social media platform
SPA/SSR frontend with service-discovered Spring Boot backend modules.
Frontend Entry
http://localhost:4200
Angular 21 app with auth, feed, explore, notifications, profile, settings, and admin views.
Gateway Entry
http://localhost:8080
Single API ingress with routing, JWT validation, and CORS control.
Core Data Stores
Service-owned MySQL schemas
Each domain service persists to its own dedicated MySQL database.

2Detailed Requirements

Functional Scope

Identity and access: registration, login, forgot-password, OTP verification, reset-password, profile update, password change, account deactivation, account deletion, and Google OAuth2 callback handling.
Content creation: users can create posts with visibility levels PUBLIC, FOLLOWERS, and PRIVATE, then edit, delete, and search them.
Conversation layer: comments support post-level discussions, reply threads, per-comment like state, like counters, and post comment count synchronization.
Social graph: follow and unfollow operations, follower/following counts, mutual connections, and suggestion retrieval are provided as a dedicated service.
Attention and discovery: stories, unread notifications, hashtag trending, post search, and user search support daily platform engagement.
Administration: admins can view dashboard metrics, inspect users, change roles, change status, verify or deny verification, and delete user accounts.

Non-Functional Expectations

Loose service coupling Gateway-based security Independent schema ownership Asynchronous event propagation Admin observability Local Docker-friendly startup

12Core User Flows

Post Engagement Flow

Create: the feed or composer submits post content through /api/v1/posts, and the post service stores the content in the posts schema.
Attach media or story content: media-related payloads are handled through the media service so post assets and stories remain isolated from the main post service.
React and comment: likes go through the like service and comment threads go through the comment service, while counters are synchronized back to the post service.
Notify and index: Kafka-backed downstream consumers can transform activity into notifications and searchable hashtag metadata.

Story and Discovery Flow

Story publish: the client sends story payloads to /api/v1/stories, and the media service stores story metadata with an expiring lifecycle.
Story feed retrieval: the frontend requests /api/v1/stories/feed and hydrates story cards for the user dashboard.
Search and hashtags: search screens query users, posts, and trending hashtags through dedicated search endpoints.

16Security and Ops

JWT-based access: the gateway validates tokens and forwards trusted identity context to downstream services.
Role-sensitive routes: the Angular client uses authGuard, guestGuard, and adminGuard to separate guest, authenticated, and admin experiences.
OAuth2 support: Google sign-in is configured in the auth service and returns users through the gateway callback flow.
Operational visibility: Actuator endpoints are exposed across services, Eureka tracks registrations, and Spring Boot Admin provides a centralized runtime view.
CORS and environment configuration: allowed origins include local frontend hosts, while secrets such as JWT, Google OAuth, mail, and Razorpay values can be externalized with environment variables.

17Future Enhancements

Add richer real-time delivery for notifications, typing indicators, and live feed refresh instead of relying only on request-response refresh patterns.
Introduce object storage and CDN-backed media delivery so post media and stories scale independently from the relational metadata services.
Formalize an API documentation portal by aggregating Swagger/OpenAPI documents from all services behind the gateway.
Expand moderation with report queues, content review workflows, and audit trails connected to admin actions.
Add automated expiry cleanup, search reindex tools, and observability dashboards for production-readiness.
